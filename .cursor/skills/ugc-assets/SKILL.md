# UGC 素材の調達と検品

## このスキルが存在する理由

**新しく作る前に、手持ちを見ていないことが事故になる。**

実例（2026-08-07・Kivori 2本目）: 「録音しているところ」のカットが要るとなり、手元の実機録画
`app-recording.mp4` を挿し込もうとした。その録画は**山本さん**（SaaS の CTO・リファラル採用）の
デモで、本編の背景カードは台本が指定する**田中さん**（柴犬・ドッグラン）だった。並べれば人物が
入れ替わって見える。気づいたのは素材の中身をフレーム単位で開いた後で、それまでの検討はすべて
やり直しになった。**最初に棚卸ししていれば一手で分かっていた。**

素材は「足りないから作る」より「あるのに気づかない」「あるが混ぜられない」で失敗する。
だからこのスキルの順番は、調達より棚卸しが先に来る。

## 全体の流れ

```
[台本 / 撮影指示書から来た素材リスト]
      ↓
0. 棚卸し     ── 手持ちに使えるものが無いか。スクリプトで機械的に
      ↓
1. 振り分け   ── 手持ち / ダウンロード / 生成 / 実機 のどれで取るか
      ↓
2. 調達       ── 経路ごとの作法。生成は buzzy-video-prompt へ渡す
      ↓
3. 検品       ── 揃った素材を並べて、混ぜられるかを確認
      ↓
[合成へ]
```

素材リストが手元に無い状態で呼ばれることもある（「この素材使える?」だけの相談）。
その場合は 0 と 3 だけを回せばよく、台本を作りに行かない。

---

## 0. 棚卸し（新しく作る前に必ず)

```bash
python3 scripts/probe_assets.py <assets ディレクトリ> --target 9:16
```

ファイル名・種別・解像度・アスペクト比・尺・音声の有無を一覧にし、目標比率から外れたもの、
音声が無い動画、読めなかったファイルを警告として出す。目視だと似た名前の別テイクや過去の
失敗作を見落とすので、機械に出させる。

中身を見る必要があるものは、フレームを抜いて横に並べる:

```bash
python3 scripts/contact_sheet.py <video> -o /tmp/sheet.png --count 5
python3 scripts/contact_sheet.py <video> -o /tmp/sheet.png --times 0.5,4,9.3,13.8
```

1 枚ずつ開くより往復が減るうえに、**時系列の変化**（人物が入れ替わる・言語設定が違う・途中で
画角が変わる）が一目で分かる。上の山本さん／田中さんは、これを最初にやれば即座に出ていた。

棚卸しの結果は、使える・使えない・条件付きで使えるの 3 つに分けてユーザーに出す。
「条件付き」には条件を書く（例: 「9:16 ではないので合成側で切る前提なら可」）。

---

## 1. 振り分け

素材ごとに 4 経路のどれで取るかを決める。**迷ったら安い順・速い順に試す**のが基本だが、
その素材が動画の見せ場かどうかで判断が変わる。見せ場は品質を優先する。

| 経路 | 向いているもの | コスト | 注意 |
|---|---|---|---|
| **手持ち** | 過去テイク・画面録画・素材写真 | 0 | 前提の食い違い（人物・時刻・言語）を検品で必ず見る |
| **ダウンロード** | 背景・B ロール・環境音・BGM | 0〜 | ライセンスと、実在の人物・店名・ロゴの写り込み |
| **生成（Buzzy）** | 人物・演技・実写では撮れない画 | 有料 | **buzzy-video-prompt に渡す。ここが有料ライン** |
| **実機で撮る** | アプリ画面・手元の操作 | 0 | 本人しか撮れない。撮影指示書は ad-copy の Format D |

判断で効く材料が 2 つある。

**アプリ画面は実機かシミュレータで撮るのがいちばん強い。**市場調査（ad-copy の Step 2）で
繰り返し出てくる所見が「実機を手で触っている画は、画面録画そのものよりエンゲージメントが
高い」。生成で作れる画ではないし、生成する理由も無い。

**シミュレータは実機の代わりになることがある。**開発中のアプリなら、ビルドしてシミュレータで
撮れば、ステータスバーを固定でき（`xcrun simctl status_bar override`）、実際にタップして
本物の UI 状態に入れる。実機を出してもらうより速い。ただし**マイク入力や端末固有の機能は
動かない**ので、そこは実機が要る。

---

## 2. 経路ごとの作法

### 手持ち

棚卸しで見つけたものをそのまま使う前に、検品（3）を通す。**「前に使ったから大丈夫」は根拠に
ならない**。前に使った文脈と今回の文脈が同じとは限らない。

### ダウンロード（ストック素材）

- **ライセンスを確認して記録する。**どのサイトのどの ID を、どの条件で使ったか。後から
  外せなくなる
- **実在の人物・店名・企業ロゴ・コミュニティ名が写り込んでいないか**を見る。UGC は「本人が
  撮った」体で出すので、写り込みは本人が承諾したように読まれる
- 素材然とした画は UGC の前提を壊す。市場データ上、勝っているのは生活感のある画で、
  きれいなストック映像ではない

### 生成（Buzzy）

**ここが有料ライン。`buzzy-video-prompt` に渡す。**単価・失敗メカニズム・生成前ゲートは
すべてあちらが持っているので、このスキルで作法を二重に書かない。

このスキルの担当は、**渡す前に「本当に生成が要るか」を確認すること**。手持ち・ダウンロード・
実機で足りるものを生成に回すと、そのまま有料ラインを踏む。

### 実機で撮る

撮影指示書は ad-copy の Format D が持つ。このスキルの担当は、**指示書に載せる撮影条件のうち、
素材として成立するために必要な項目**を渡すこと。具体的には解像度と向き、ステータスバーの状態、
通知の抑止、映り込ませてはいけないもの。

---

## 3. 検品（合成に渡す前）

**個々の素材が良くても、混ぜられるとは限らない。**ここで見るのは素材同士の整合性。

| 見るもの | 何が起きるか | 実例 |
|---|---|---|
| **人物の同一性** | 別人が入れ替わって見える | 山本さん素材 × 田中さんカード（2026-08-07） |
| **時刻・ステータスバー** | 別の日の画に見える | 実機 14:51 + 録画中の赤丸 × シミュレータ 9:41 |
| **言語設定** | 日本語動画に英語 UI が出る | 録音画面の言語チップが English 選択のまま |
| **アスペクト比** | 引き伸ばし・見切れ | 992×432 の横向きテイクが 9:16 の本編に混ざる |
| **尺** | スロットに入らない | 音声 3.47s をスロット 3.3s に置いて末尾が切れる |
| **音声の有無** | 無音区間ができる | 素材クリップが muted なのに気づかない |
| **実在名の映り込み** | 実在の店・人・コミュニティを広告に載せる | 入力シートの場所欄のヒントに実在のコミュニティ名が入っている |

上 4 つは `probe_assets.py` と `contact_sheet.py` で機械的に出せる。下 3 つは目で見る。

**通らなかったものは、合成に進ませず経路の振り分け（1）に戻す。**「とりあえず合成して後で
差し替える」は、差し替えが起きないまま完成扱いになりやすい。

---

## 記録

調達した素材は、どこから来たのかが後で分からなくなる。次の 3 つは残す。

- **出所**（ダウンロード元と ID / 生成のプロンプトとモデル / 撮影の日時と端末）
- **ライセンス**（ストック素材の場合）
- **使えなかったものと、その理由**（同じ失敗を二度やらないため。実例: 992×432 の横向き
  テイクは「演技は合格だが比率が違う」で保管されている）

書き先はプロジェクトの記録場所に従う。Obsidian vault を使っているプロジェクトなら
`obsidian-os` スキルが担当する。

---

## 他のスキルとの境界

このスキルは素材だけを持つ。以下は持たない。

| 対象 | 担当 |
|---|---|
| 需要リサーチ・企画・台本・撮影指示書 | `ad-copy` |
| Buzzy の生成前ゲート・単価・不具合の切り分け | `buzzy-video-prompt` |
| 記録を vault へ書く | `obsidian-os` |

境界をまたぐ依頼が来たら、自分で書かずにそのスキルへ渡す。単価表のような数字を二重に持つと、
片方だけ古くなって静かに間違う。

## 同梱スクリプト

| スクリプト | 用途 |
|---|---|
| `scripts/probe_assets.py` | ディレクトリの棚卸し。解像度・比率・尺・音声を一覧化し、目標比率から外れたものを警告 |
| `scripts/contact_sheet.py` | 動画からフレームを抜いて横一列に並べる。中身と時系列変化の確認用 |

どちらも ffmpeg / ffprobe が要る。`contact_sheet.py` は Pillow も使う。
