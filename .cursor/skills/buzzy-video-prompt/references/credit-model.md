## 1. クレジット消費構造

buzzy.now は**テキスト対話・事前計画フェーズ**と**動画レンダリングフェーズ**で
消費ルールが明確に分離されている。この境界を理解していないと、
無料でできる作業を飛ばして有料の当たり直しを繰り返すことになる。

### Phase 1: 事前計画・テキスト構造化（Planning Phase）

- **使用機能**: Buzzy Creative Agent / AI Storyboard
- **消費**: **0 クレジット（完全無料）**
- **機能範囲**:
  - 曖昧な自然言語指示 → 構造化プロンプトへの変換
  - カメラ軌道・解剖学的動作・時間軸分割の自動定義
  - アセットの紐付け

### Phase 2: 動画レンダリング（Rendering Phase）

- **使用機能**: Video Generator Node（Seedance 2.5 / 2.0 Engine）
- **消費**: **1 生成あたり約 75 クレジット**
- **発生トリガー**: UI 上の「Generate（レンダリング実行）」ボタン押下時

> 実測 (2026-08-05): **静止画の生成は 1 枚 7 クレジット**(9:16・1k。残高 3105 → 3098 で確認)。
> **動画は 480p・5s で 55 クレジット**(start & end frame・残高 3098 → 3043 で確認)。
> 「約 75」は固定値ではなく解像度・尺で変わる可能性が高い。720p 以上は未実測。
> 「Phase 1 = 完全無料」はテキスト構造化・計画の話で、**キャンバス上の画像生成は少額だが有料**。
>
> 実測 (2026-08-05・start & end frame モード): 開始・終了フレームの**画角が揃っていないと、
> 補間が緩いズームとして現れる**(腰上→胸上で自然なプッシュインになった)。カメラ固定を
> 指示しても両端フレームに引っ張られる。固定したいなら**先に 2 枚の画角を揃える**(E 層の問題)。

> **有料ラインは Generate ボタン 1 点のみ。**
> それ以前の構造化・参照設定・UI 設定はすべて 0 クレジット。
> つまり**無料側でやれることを全部やり切ってから 75 を払う**のが唯一の最適化。

## 2. コスト計算モデル（15 秒の OK テイク 1 本）

| 制作パターン | Generate 回数 | 総消費 | 条件 |
|---|---|---|---|
| ① 完全制御（一発成功） | 1 回 | **約 75** | Creative Agent でプロンプトを 100% 構造化し、参照画像を事前固定して出力 |
| ② 標準制作（推奨基準） | 2 回 | **約 150** | 1 回目の微妙な揺れ・表情を修正プロンプトで微調整し、2 回目で完成 |
| ③ 非効率制作（調整難航） | 3〜4 回 | **約 225〜300+** | **非構造化文脈や否定表現（「〜しない」等）を使い、75 クレジットの生成を連打した場合** |

> ③ は事故ではなく**書き方から決まっている結果**。
> 否定表現と非構造化文脈は、①に対して**3〜4 倍のコスト**として現れる。
> 「とりあえず投げてみる」の実売価格がこれ。

## 3. Generate 前に定義する 6 構成要素

75 クレジットの無駄打ちを防ぐため、Generate を押す前に Creative Agent 上で以下を定義する。

1. **Camera Command（カメラパラメータ）**
   移動軌道（Z 軸アプローチ・速度・画角変化）を明記。
   **カメラ固定時**: プロンプトに `Locked static tripod shot` 等を記載し、
   **UI 側のレンズ設定を「Fixed（固定）」に選択する**。
   （動かす場合は「Not Fixed」。プロンプトと UI 設定の向きを一致させる）

2. **Subject & Micro-Expressions（被写体・解剖学的動作）**
   抽象的な感情名（例: 悲しい）を避け、解剖学的な物理運動として記述する。
   まぶたの下がる速度、口角の上昇、唇の離間など。

3. **Temporal Progression（時間軸ビート分割）**
   `0-2s / 2-4s / 4-6s` のように、時間経過に伴う変化を明示的に区切る。

4. **Isolating Constraints（静止条件・ハルシネーション遮断）**
   主動作以外の部位および背景幾何構造を `motionless / locked` として制約する。

5. **Reference Asset Binding（参照アセットバインディング）**
   `@Character1` `@MotionClip1` 等のロールタグで、参照画像/動画とテキストを直接紐付ける。

6. **UI Field Isolation（UI パラメータの分離）**
   アスペクト比（9:16 等）・解像度（480p / 1080p）・生成時間（5s / 15s）・
   使用モデル（Seedance 2.0 / 2.5）は**プロンプト本文に書かず、
   必ず UI の各専用設定フィールドで指定する**（トークン消費の防止）。

## 4. モデルバージョン別の運用制約

> ⚠️ **原文の読み違いに注意（2026-08-05 訂正）**
> 仕様書の原文は「Region-Level Editing、Omni Reference（**最大 50 個参照**）、ネイティブ 30 秒生成は
> **未対応または仕様が異なる**ため前提としない」。
> **「または仕様が異なる」を落として「機能ごと未対応」と読むと誤る。**
> Omni Reference は 2.0 でも使え、差は**上限数（12 / 50）と最大尺（15s / 30s）**という規模。
> 一方 Region-Level Editing は 2.0 で**未対応**（＝可否の差）。この 2 種類を混同しない。

### 機能対応表

| | Seedance 2.0 | Seedance 2.5 |
|---|---|---|
| **Omni Reference** | **使える**（画像・動画・音声 合計 **最大 12 アセット**） | 使える（**最大 50 アセット**） |
| **最大生成尺** | **15 秒** | 30 秒 |
| **Region-Level Editing** | **未対応** | 利用可能 |
| 3D Blockout メッシュ（OBJ 等）・音響同期・詳細ロールタグ | 限定的 | 対応 |

### Seedance 2.0

- **使えるもの**: Omni Reference によるキャラクター固定（`@Image1` `@Video1` 等のロールタグ指定）。
  顔・衣装・構図のブレを抑えられる。**「2.0 だから同一性を諦める」は誤り。**
- **制約**: Region-Level Editing が無い。参照は 12 アセットまで。1 本 15 秒まで。
- **方針**: 「失敗したら後から局所修正する」という選択肢を**排除する**。
  事前に UI 設定（Fixed Lens 等）・Omni Reference・肯定表現プロンプトを完備して**一発生成**を行う。

### Seedance 2.5

- **機能**: Region-Level Editing（範囲指定部分再描画）が利用可能。参照 50 / 尺 30 秒。
- **方針**: 全体の動きやカメラワークが成功し、顔の表情や手元など特定部分のみ不具合がある場合は、
  **75 クレジットを使って全体を再生成せず**、領域指定修正で局所的に修復する。

> この分岐は B の不具合ルーティングの前提そのもの。
> **2.0 で「Region Editing で直しましょう」と言うのは、存在しない逃げ道を勧めることになる。**
> **逆に「2.0 だから Omni Reference が使えない」も誤り。**

## 5. 標準ワークフロー（SOP）

| # | 区分 | 手順 |
|---|---|---|
| 1 | **[無料]** | Creative Agent を起動し、作成したい映像の構図・被写体・カメラワークを入力する |
| 2 | **[無料]** | Agent にプロンプトを「カメラコマンド・解剖学的動作・タイムラインビート・静止制約」の構造化テキストへ変換させる |
| 3 | **[無料]** | Buzzy Visual Canvas に参照画像をセットし、ロールタグで紐付ける |
| 4 | **[設定]** | UI フィールドで Model: Seedance / Lens: Fixed（または Not Fixed）/ Aspect Ratio / Resolution を設定する |
| 5 | **[有料]** | Generate を実行し、動画を出力する（**約 75 クレジット消費**） |
| 6 | **[修正]** | 必要に応じて Region Editing を使用するか、微調整プロンプトを投入して完成させる（累計 75〜150 クレジット） |

**1〜4 は全部無料。ここを飛ばして 5 に行くのが、③のコスト構造に落ちる唯一の道。**
