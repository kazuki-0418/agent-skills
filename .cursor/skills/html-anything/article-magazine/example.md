# @trq212 のあのツイートを読んだあと, すべての markdown を HTML に換えた

> 着想の原文: https://x.com/trq212/status/2052809885763747935
>
> 要するに: AI 執筆 / エディタ / エージェントの時代, markdown という"中間形態"はもう持たない —— HTML こそ読者向けの最終形態だ。

## うなずいた三つの観察

第一, markdown への愛は, 主に書いていて気持ちいいからだ。だが読者は一度も投票していない。
読者が受け取るのはいつでも, どこかの markdown レンダラーが吐き出した結果 —— そしてそのレンダラーはプラットフォームのもので, あなたのものではない。

第二, スクリーンショットをツイートする件では, markdown は負けた。
markdown をどれだけ切り出してスクショしても, GitHub のデフォルトテーマで潰された灰白の四角になる。HTML は壁紙級の画像にできる。

第三, 公式アカウント / 知乎 / 小紅書 / Notion / 飛書 —— 各社の markdown の解釈はみな違う。
1 本書いて, 5 つのプラットフォームで 5 回調整する。HTML + インライン CSS, 一度貼れば, どのプラットフォームでも再現される。

## だが HTML は冗長すぎる, これは本当だ

`<div class="...">` 書きすぎると吐き気がする, これは事実だ。
以前は誰も HTML を書くコストを払いたくなかった, 同じ内容なら markdown 30 秒, HTML 30 分だから。

変数は —— **AI がこの 30 分を 30 秒に下げた**。
あなたは markdown を書く, AI がそれを納品できる HTML に上げる。最終形態はあなた, 冗長な細部は AI。

## ついでにツールを作った

着想は元ツイート, それに Claude Code チームの実践を加えて, 私たちは [HTML Anything](https://github.com/nexu-io/html-anything) を作った。
左に markdown / CSV / JSON を貼り, テンプレートを選ぶ (雑誌、PPT、ポスター、小紅書、データレポート …), ⌘+Enter を押す ——
ローカルの Claude / Cursor / Codex があなたが**すでにログイン済み**の session で走り, 数秒後に右には公式アカウント / Twitter / 知乎にそのままコピーできる HTML がある。

API Key は不要, token を無駄にしない (二次編集は diff だけ走る)。

## 結論

「markdown → エディタで手作業の再レイアウト」が人生の無駄だと感じるなら —— 元ツイートを一目, Claude Code チームの移行を一目, それから markdown を自動で HTML に昇格できるツールをどれでも試してほしい。

> 見出し画像への敬礼: ツイートのあの "everything is HTML" の瞬間。
